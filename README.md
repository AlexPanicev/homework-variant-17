## Общее описание

Транслятор читает один документ на учебном конфигурационном языке из
`stdin` и записывает результат в YAML в `stdout`. Условие задачи приведено
на страницах 40 и 41 сборника домашних заданий, правила оформления на
страницах с 4 по 7.

Синтаксис задан в файле [`src/grammar.lark`](src/grammar.lark). Lark строит
дерево разбора методом LALR, затем транслятор вычисляет константы и
выражения. PyYAML формирует YAML из вычисленного значения.
[Документация Lark](https://lark-parser.readthedocs.io/en/latest/parsers.html)
и [PyYAML](https://pyyaml.org/wiki/PyYAMLDocumentation).

## Подготовка и запуск

Нужен Python 3.12 или новее и оболочка `sh`. В Windows скрипт можно
запустить в WSL. Команды ниже выполняются из корня репозитория.

```sh
git clone https://github.com/AlexPanicev/homework-variant-17.git
cd homework-variant-17
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m compileall -q src
./run.sh < examples/telemetry.cfg
```

Установка зависимостей готовит проект к запуску. `compileall` проверяет
синтаксис Python и создаёт локальные файлы байткода. При обычном запуске
эту команду можно пропустить.

- `./run.sh --help` выводит справку. Конфигурация передаётся через
  стандартный ввод, например перенаправлением `< файл.cfg`.
- Скрипт выбирает `.venv/bin/python`, если окружение создано в корне
  проекта, иначе ищет `python3` в `PATH`. Переменная `PYTHON` позволяет
  указать другой интерпретатор, например `python3.12`.
- При успешной трансляции код завершения равен `0`. Ошибка во входном
  документе даёт код `2` и сообщение в `stderr`. Синтаксические ошибки и
  ошибки вычисления содержат строку и столбец. При такой ошибке
  `stdout` остаётся пустым. Сбой ввода-вывода или отсутствие зависимости
  даёт код `1`. Прерывание через Ctrl+C даёт код `130`.

## Синтаксис и вычисления

Документ состоит из необязательных объявлений `def` и одного корневого
значения. Корнем может быть число, массив, словарь или результат выражения.
Вход читается в UTF-8, допустимы BOM и переводы строк LF, CRLF и CR.

| Конструкция | Запись и правила |
| --- | --- |
| Однострочный комментарий | `\|\|` до конца строки или ввода |
| Многострочный комментарий | `%{` до ближайшего `%}`, включая переводы строк |
| Число | `[+-]?\d+\.?\d*[eE][+-]?\d+`, например `-2.5E-1` или `5.e0` |
| Имя | `[_a-zA-Z]+`, регистр учитывается |
| Массив | `<< 1e0, 2e0, {} >>`, пустой массив `<<>>` |
| Словарь | `{ rate => 1e0, items => <<>> }`, пустой словарь `{}` |
| Объявление константы | `def base := 1.25e0;` |
| Подстановка константы | `!(base)` возвращает значение `base`, в том числе коллекцию |

Элементы коллекций можно вкладывать друг в друга. Перед закрывающим
разделителем непустой коллекции допустима одна завершающая запятая.
Повторяющиеся ключи в одном словаре считаются ошибкой.

Объявления обрабатываются сверху вниз. Ссылка доступна после объявления
имени. Повторное объявление считается ошибкой. В YAML попадает корневое
значение, а таблица объявлений используется только при трансляции.
При повторной подстановке одной коллекции YAML может содержать якорь и
ссылку на него.

Префиксная операция принимает два операнда. Операндом может быть имя
числовой константы, число с экспонентой, целое со знаком или без него
либо результат вложенного выражения. Целый операнд поддерживает запись
`!(+ base 1)` из методички. Вложенную операцию можно записать как
`!(+ !(- base 1) 2)` или `!(+ (- base 1) 2)`.

| Операция | Пример | Результат |
| --- | --- | --- |
| Сложение | `!(+ 1e-1 2e-1)` | `0.3` |
| Вычитание | `!(- 5 8)` | `-3` |
| Остаток | `!(mod -5 3)` | `1` |

`mod` вычисляет `a - b × floor(a / b)`. Ненулевой остаток имеет знак
делителя. При нулевом делителе или коллекции в арифметической операции
транслятор сообщает об ошибке.

Для точной десятичной арифметики показатель степени хранится отдельно
от целого коэффициента. Целое число записывается десятичными цифрами,
если они помещаются в допустимый объём вывода. Дроби и более длинные
целые записываются в экспоненциальной форме с сохранением всех цифр.
Точность после загрузки YAML зависит от числового типа в
программе-получателе.

CLI принимает до 1 МиБ входа и формирует до 4 МиБ YAML. Вложенные
коллекции обходятся с помощью стека. Если вывод превышает допустимый
объём, транслятор пробует компактную запись коллекций и чисел.
Если для точного промежуточного вычисления требуется больше разрядов,
чем вмещает объём вывода, CLI сообщает позицию и причину ошибки.

## Проверка

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/check_quality.py
```

Тесты проверяют конструкции языка, вычисление констант, преобразование
трёх предметных примеров и работу CLI. Среди граничных случаев есть
число `1e4097` и коллекции с тысячами уровней вложенности. Негативные
тесты охватывают ошибки синтаксиса, кодировки, типов и арифметики.
`check_quality.py` использует Ruff, Radon и анализ Git для контроля
оформления. Те же проверки запускаются в GitHub Actions.

Например, команда ниже завершится с кодом `2` и пустым `stdout`.

```sh
printf '%s\n' '{ rest => !(mod 5 0) }' | ./run.sh
```

```text
Ошибка: строка 1, столбец 13: остаток от деления на ноль
```

## Примеры использования

### Телеметрия датчиков

[`examples/telemetry.cfg`](examples/telemetry.cfg) задаёт интервалы
опроса и номера каналов.

```text
%{
Интервалы опроса датчиков в секундах.
%}
def interval := 2.5e0;
def count := 8e0;
{
    polling => {
        period_seconds => !(interval),
        delayed_seconds => !(+ interval 1),
    },
    channels => <<0e0, 1e0, !(- count 1)>>,
}
```

```sh
./run.sh < examples/telemetry.cfg
```

```yaml
polling:
  period_seconds: 2.5e+0
  delayed_seconds: 3.5e+0
channels:
- 0
- 1
- 7
```

### Музейные экскурсии

[`examples/museum.cfg`](examples/museum.cfg) задаёт вместимость группы,
расписание и список отменённых сеансов.

```text
|| Часы начала экскурсий и вместимость группы
def capacity := 2.4e1;
def slots := <<1e1, 1.4e1, 1.6e1>>;
{
    group => {
        capacity => !(capacity),
        reserve => !(- capacity 4),
    },
    session_hours => !(slots),
    cancelled => <<>>,
}
```

```sh
./run.sh < examples/museum.cfg
```

```yaml
group:
  capacity: 24
  reserve: 20
session_hours:
- 10
- 14
- 16
cancelled: []
```

### Упаковка товара на складе

[`examples/warehouse.cfg`](examples/warehouse.cfg) задаёт объём партии
и рассчитывает остаток после упаковки в полные коробки.

```text
|| Остаток после упаковки партии
def unit_count := 5.3e1;
def box_size := +1.E+1;
{
    batch => {
        units => !(unit_count),
        box_size => !(box_size),
        loose_units => !(mod unit_count box_size),
    },
    buffer => !(+ (mod unit_count box_size) 2),
}
```

```sh
./run.sh < examples/warehouse.cfg
```

```yaml
batch:
  units: 53
  box_size: 10
  loose_units: 3
buffer: 5
```
